Cross-repository contracts, decisions, and setup for independent Git source
trees. Seven Rust packages compose one application; the UI and reusable Core
packages are separate.

## Workspace setup

Requirements: Git, Python 3.9+, Rust/Cargo 1.85+ with rustfmt and Clippy, and Node
18+ for the UI boundary. Install the Rust components with `rustup component add
rustfmt clippy` if absent. The scripts do not install tools or alter Git branches.

```sh
python3 .planning/scripts/bootstrap_tempo.py .
python3 .planning/scripts/qualify_scaffold.py .
cargo build -p tempo
node tempo/demo/run.mjs
```

Run those commands from the parent containing the sibling repositories. For a
fresh machine, clone `.planning` into `~/Developer/tempo-v2/.planning`, then run
its bootstrap with `~/Developer/tempo-v2` as the destination. `--protocol ssh`
selects SSH for new clones; existing valid origins are preserved.

Copy the [canonical agent guidance](agent-guidance/AGENTS.md) into the assembled
workspace before agent work. From the workspace root:

```sh
test -e AGENTS.md || cp .planning/agent-guidance/AGENTS.md AGENTS.md
```

If a root copy already exists, merge the canonical guidance into it and retain
any applicable local instructions. Update the tracked canonical copy when the
shared guidance changes.

Read the tracked canonical file at the start of each task even when a copied
root file already exists. The planning repository's root AGENTS.md points to
that one source. Changes here are not automatically installed on another machine.

Bootstrap creates a local virtual workspace and local Cargo patches for the
unpublished sibling packages. Package manifests retain standalone metadata and
version requirements. The parent is not a Git repository. The UI and `.planning`
are excluded from Cargo membership. Every Tempo dependency must resolve to its
expected local checkout before the default build check proceeds.

When the Tempo checkout supplies the local launch target, bootstrap creates
a root Makefile if one is missing. For an existing Makefile, add
`include tempo/tools/local.mk` after your existing targets to enable
`make start` while keeping your default target.

An exact root manifest generated by the earlier bootstrap is upgraded to add
local patches after saving `Cargo.toml.before-local-patches`. Customized manifests
remain untouched; use [workspace.template.toml](workspace.template.toml) to merge
the patch entries. Existing source files are preserved. The script does not
pull, reset, switch branches, commit or push. `--no-check` skips dependency
resolution and compilation.

## Reading and contributing

Begin with [READING_GUIDE.md](READING_GUIDE.md). Each component README maps a
question or public concept to a source file and a runnable example. Rust files
start with purpose/when-to-use documentation and keep usage scenarios in their
own `#[cfg(test)]` module. Public root imports remain convenient; implementation
files are named for the concepts they explain.

## Development checks

Use `cargo test -p tempo-study` (or the affected package) for isolated component
work. `cargo doc --workspace --no-deps --open` builds the API reading surface. UI checks run with `node --test` from `tempo-core-components`; they need no
Rust process or database. `cargo test -p tempo --test contracts` checks application
composition. `node --test tempo/tests/ui_boundary.mjs` checks the real Rust/UI
protocol after building `tempo`.

The full qualification script is for the initial cross-repository contract and
changes spanning its boundaries. It checks the dependency graph, negative
architecture cases, workspace migration, Rust contracts/lints and warning-free documentation, UI behavior, and
the actual stdio round trip. It does not qualify real PGN parsing, FSRS, SQLite
constraints/durability, or browser rendering.

The demo is process-local and uses known chess fixtures. Its JSON-line transport
can also be inspected with `cargo run -p tempo -- stdio`. The normal next/answer
path has no game-provider dependency.
